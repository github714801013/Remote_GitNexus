# 索引落后与调度优化实现 — 验收条件与必测场景清单

- 任务：`index-scheduling-optimization`
- 依据：`index-scheduling-optimization-澄清定稿.md`
- 编号规则：验收 1..N，不跳号；下游引用本编号。

## 验收条件

### 验收 1 — 同分支差异较大的仓库优先调度

- 现象：巡检调度顺序按同分支 `commitsBehind` 从大到小排列。
- 前置：registry 中存在至少两个同分支 stale 仓库，A 落后 340、B 落后 125；进程无失败隔离记录。
- 动作：触发 `POST /api/index-health-check`。
- 可观测结果：`Stale index analyze scheduled` 日志中 A 出现在 B 之前（判定方式：日志顺序 =）；每个条目包含 `commitsBehind` 数值（判定方式：字段存在 =）。
- 维度：正向、边界；覆盖层级：接口 + 日志；覆盖用例：T01；数据可复用：是；数据准备：现成（dev-oanew、dev-nc-segments）。

### 验收 2 — 每轮最多调度 10 个仓库

- 现象：单轮巡检入队的仓库数不超过 10。
- 前置：存在 ≥ 11 个满足条件的 stale 仓库。
- 动作：触发一次 `POST /api/index-health-check`。
- 可观测结果：本轮 `Stale index analyze scheduled` 日志条数 ≤ 10（判定方式：计数 ≤）；第 11 个及之后的仓库不出现在本轮日志（判定方式：仓库名不出现 =）。
- 维度：边界；覆盖层级：接口 + 日志；覆盖用例：T02；数据可复用：是；数据准备：现成。

### 验收 3 — 跨分支假差异仓库被跳过

- 现象：索引分支与 checkout 分支不一致的仓库不再进入分析队列。
- 前置：`oa-order` registry 分支为 `release_9ji`，checkout 当前分支不是 `release_9ji`。
- 动作：触发一次 `POST /api/index-health-check`。
- 可观测结果：日志包含跳过记录，含仓库名与两个分支值（判定方式：⊇ 包含 `oa-order`、`release_9ji`、`skip` 或等价字段）；该仓库不出现 `Stale index analyze scheduled`（判定方式：不出现 =）。
- 维度：逆向、一致性；覆盖层级：接口 + 日志；覆盖用例：T03；数据可复用：是；数据准备：现成（oa-order）。

### 验收 4 — 分析失败仓库在进程内隔离

- 现象：巡检路径中分析失败的仓库，下一轮巡检不再入队。
- 前置：模拟 `enqueueWebhookAnalyze` 对仓库 X 失败一次；进程未重启。
- 动作：连续触发两轮 `POST /api/index-health-check`。
- 可观测结果：第一轮日志出现 X 的失败记录；第二轮日志中 X 不出现 `Stale index analyze scheduled`（判定方式：不出现 =），且出现隔离跳过记录（判定方式：⊇ `X` + `isolat`/`skip`）。
- 维度：逆向、状态；覆盖层级：组件层 + 日志；覆盖用例：T04；数据可复用：否（失败状态影响后续轮次，需重置进程或隔离集合）；数据准备：需造（测试桩模拟失败）。

### 验收 5 — 差异小于阈值的仓库保持原有行为

- 现象：`commitsBehind < 100` 的同分支 stale 仓库仍按原有条件被调度。
- 前置：仓库 Y 同分支落后 17。
- 动作：触发一次 `POST /api/index-health-check`（候选不足 10 个）。
- 可观测结果：Y 出现在 `Stale index analyze scheduled` 日志中（判定方式：出现 =）。
- 维度：兼容回归；覆盖层级：接口 + 日志；覆盖用例：T05；数据可复用：是；数据准备：现成（9ji-admin 17）。

### 验收 6 — webhook 路径不受巡检限量与隔离影响

- 现象：Gitea webhook 触发的分析不因巡检限额或失败隔离而被拒绝。
- 前置：仓库 X 已在巡检失败隔离集合中。
- 动作：向 webhook 接口发送 X 的 push 事件。
- 可观测结果：webhook 路径返回接受状态（判定方式：HTTP 2xx =）；分析队列出现 X 的 job（判定方式：出现 =）。
- 维度：一致性、兼容回归；覆盖层级：接口；覆盖用例：T06；数据可复用：否；数据准备：需造（webhook 载荷与签名配置）。

### 验收 7 — 并发配置与单槽行为保持不变

- 现象：本轮改动不影响既有并发模型。
- 前置：环境变量保持 `GITNEXUS_NIGHTLY_PARALLEL_ENABLED=false`、结构与嵌入并发 1。
- 动作：部署后触发巡检。
- 可观测结果：日志不出现 `[webhook] queue entered resource-aware parallel mode`（判定方式：不出现 =）；同一时刻 `Analyze worker started` 对应的活动 job 数为 1（判定方式：计数 =）。
- 维度：一致性、并发；覆盖层级：接口 + 日志；覆盖用例：T07；数据可复用：是；数据准备：现成（当前部署配置）。

### 验收 8 — 进程重启后失败隔离清空

- 现象：服务重启后，上一进程的失败隔离不再生效。
- 前置：仓库 X 在进程 A 中被隔离。
- 动作：重启服务，触发巡检。
- 可观测结果：X 重新出现在候选判断流程中（若仍 stale，则出现调度日志；判定方式：出现 =）。
- 维度：边界、状态；覆盖层级：组件层；覆盖用例：T08；数据可复用：否；数据准备：需造（重启服务）。
